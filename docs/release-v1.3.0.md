# MijiaDesk 定制版 v1.3.0

这版集中在三件事：软件改名为 **MijiaDesk**，把双摄摄像头真正接通，把检查更新修好。

## 改名：MijiaDeck → MijiaDesk

- 程序名、窗口标题、托盘提示、诊断报告、构建产物（`MijiaDesk.exe`）统一为 MijiaDesk；
- 配置目录 `%LOCALAPPDATA%\MijiaDeck` → `%LOCALAPPDATA%\MijiaDesk`，**首次启动自动迁移**旧目录里的设置、托盘布局、设备缓存与账号档案（只复制、不覆盖已有值、不删旧文件）；
- 开机自启动的注册表条目名同步改名，读开关时就地迁移，用户不需要重新开一次；
- 上游项目名仍是 MijiaDeck，署名与链接保持原样。

## 双摄摄像头：枪机画面不再是云台画面

上一版给「云台 + 枪机」机型做镜头切换时判断错了：以为第二路靠 MIoT 属性
`hl-camera-switch` 或者中继请求里的 `channel` 字段来选择。这次抓帧逐项验证，
结论是两者都不成立：

- 发 `{"videoquality":1,"channel":1}` —— 设备完全忽略 `channel`，画面和
  `channel=0` 逐像素一致；
- 写 `hl-camera-switch`（siid 6 / piid 21）为 2、或改 `dome-switch` /
  `box-switch`，再重连 —— 画面依旧；
- 用「发云台转向指令，看画面是否跟着动」做判别，确认拿到的始终是云台那一路。

正确做法是 MISS 视频请求体里的**双码流写法**：主码流置 -1，第二路写进
`videoquality2`：

```json
{"videoquality":-1,"videoquality2":3,"enableaudio":0}
```

另外还有一个前置条件：目标镜头的电源开关必须是开的（`siid 6 piid 25`
云台、`piid 26` 枪机）。关着那一路时，请求能连上但没有任何画面，表现就是
「等待摄像头画面」卡住超时。`hl-camera-switch`（piid 21）只是这两个开关的
汇总读数，写它不选流。

现在的行为：

- 摄像头窗口「切换镜头」菜单：云台 / 枪机两项，切换前自动给目标镜头通电；
- 九宫格里双摄那一格多一个「云台 / 枪机」按钮，切完等 3~6 秒出画面；
- 两路在「全分辨率」档都是 2560×1440，480P 档是 640×360。

### 双画面：两个镜头同时看

同一台设备能同时承载两路会话，所以新增「双画面（云台 + 枪机并排）」。
入口在摄像头窗口和九宫格格子的「镜头」菜单里，打开后是一个两格窗口，
两路各自 480P（可切全分辨率）、各自显示自己的状态。

两个实测出来的约束已经写进实现：

- **不能同时鉴权**：并发开两路时设备只认后到的那个，先到的那路会被踢掉。
  所以先开云台，等它真的出帧（最多 6 秒）再开枪机；
- **不能共用一份授权参数**：两路要各自 `prepare_camera_source`，否则同样互顶。

## 摄像头墙

- **一个 JVM 承载多路**：中继改成多会话宿主（`OPEN` / `CMD` / `CLOSE` /
  `QUIT` 行协议），九宫格不再每格起一个 `java.exe`。5 路时进程数从 5 个
  降到 1 个，冷启动和内存都省下来了。
- **大窗独占**：点某格右上角「大窗」或点右下角全屏，其余格子会立刻断开
  （会话、解码、上行全停），标题显示「大窗播放中，其余已暂停」；关掉大窗
  自动按原顺序恢复。原来九路同时拉流会把上行和核显一起打满。
- **全量软件解码**：核显硬解在 5 路 HEVC 下会耗尽 D3D11 解码表面池，直接
  `DXGI_ERROR_DEVICE_REMOVED` 崩进程，现在统一走 ffmpeg 软解。
- **每格画面铺满**：格子的比例（约 1.18）和 16:9 画面不一致，原来按完整
  显示绘制，上下各留几十像素黑边，看着像画面没铺开；现在按「覆盖」缩放后
  居中裁剪，画面填满整格。单摄像头窗口仍是完整显示，不裁切。
- 画质只保留 480P / 全分辨率两档。

## 检查更新

「检测更新」点了没反应，其实是两件事叠在一起：

1. 本仓库只有 `v1.2.0` 这个 tag，**从来没有创建过 release**。GitHub 对没有
   release 的仓库，`/releases/latest` 会 302 到列表页，旧代码把它当成「网络
   不可用」，提示词完全误导；重试多少次都不会成功。
2. 结果反馈用的是右下角一闪而过的 Toast，又挂在模态遮罩上，基本看不见。

现在：

- 检查结果直接写在关于面板的状态行里（检查中 / 已是最新 / 发现新版本 /
  失败原因），不会再「点了没反应」；
- 识别「仓库还没有发布任何版本」这一独立状态，与真正的网络故障分开提示；
- 首页脚注的手动检查同样区分这两种情况。

## 升级

- 源码运行：`git pull` 后重跑 `run.py`。
- 便携包：先从托盘退出旧版，再完整解压覆盖原目录（保留 `_internal`）。exe 与文件夹名字变成 `MijiaDesk.exe`，旧目录里的配置会在首次启动时自动搬到 `%LOCALAPPDATA%\MijiaDesk`。
- 版本号 1.2.0 → 1.3.0。
